📍 Lesson 1.2 – print() Done Methodically (Not Randomly)

Most novices put print() everywhere and get lost.
Instead, follow three rules:

    Print at function entry – print(">>> entering compute_average")

    Print variable values before & after a suspicious line – print(f"x before: {x}")

    Print checkpoints – print("=== checkpoint 1 ===") to see how far execution goes.

In your notes, copy this example:

def buggy_function(a, b):
    print(">>> entering buggy_function")          # entry
    result = a * (b + 1)                          # suspicious line
    print(f"result after suspicious line: {result}")  # inspect
    print("=== before return ===")                # checkpoint
    return result

🔍 Lesson 1.3 – The Novice Debugging Loop (4 steps)

Write this in your notes. Memorise it.

    Reproduce – Can you make the bug happen every time? If not, find what input does.

    Isolate – Find the smallest region of code where the bug lives.
    Novice method: comment out half the code, run, see if bug still there.

    Understand – Why does that line produce the wrong value? Look at variable values.

    Fix & Test – Change one thing, run again, confirm bug gone.

In your notes, draw a simple diagram:

Reproduce → Isolate → Understand → Fix & Test
     ↑                                   |
     └───────────────(loop)──────────────┘


✂️ Exercise 1.3 – Binary search by commenting

Take this 30‑line function (it’s supposed to merge two sorted lists but returns wrong result).
Do not try to understand the whole thing. Instead:

    Comment out half the lines (temporarily replace with pass or a simple return).

    Run it. Does the bug still appear?

    If yes → bug is in the uncommented half. If no → bug is in the commented half.

    Repeat until you narrow it down to 3–5 lines.

    def merge_sorted(a, b):
    result = []
    i = 0
    j = 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            result.append(a[i])
            i += 1
        else:
            result.append(b[j])
            j += 1
    while i < len(a):
        result.append(a[i])
        i += 1
    while j < len(b):
        result.append(b[j])
        j += 1
    return result

# Test

🧪 Lesson 1.4 – Minimal Reproducible Example (MRE)

An MRE is the shortest possible code that still shows the bug.

Why you need it:

    Helps you ask for help on Stack Overflow / ChatGPT.

    Often, while stripping code, you find the bug yourself.

Rules for an MRE (write in notes):

    Remove all unrelated code (no GUI, no database if not needed).

    Replace external data with a small hardcoded array.

    Remove all dependencies that aren’t essential.

Example: Instead of 500 lines reading a CSV and doing ML, you write:


import pandas as pd
# Instead of pd.read_csv('huge.csv'), do:
data = pd.DataFrame({'x': [1,2,3], 'y': [4,5,6]})
# Then reproduce the bug on this tiny data.
